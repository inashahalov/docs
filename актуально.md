## 🔑 SQL: 4 критических блока для миграции

| Блок | Зачем нужно | Минимум для работы |
|------|-------------|-------------------|
| **1. Сравнение данных (валидация)** | После миграции проверяешь: «всё ли переехало без потерь» | ```sql<br>-- Сравнение кол-ва записей<br>SELECT COUNT(*) FROM src_table;<br>SELECT COUNT(*) FROM tgt_table;<br><br>-- Сравнение агрегатов<br>SELECT SUM(amount), AVG(balance) FROM src_table;<br>SELECT SUM(amount), AVG(balance) FROM tgt_table;<br><br>-- Поиск расхождений по ключу<br>SELECT id FROM src_table<br>EXCEPT<br>SELECT id FROM tgt_table;``` |
| **2. Оконные функции** | Нормализация «фантомов», разделение дублей, ранжирование | ```sql<br>-- Найти дубли по продукту + клиенту<br>SELECT *,<br>  ROW_NUMBER() OVER (<br>    PARTITION BY product_id, client_id<br>    ORDER BY created_at DESC<br>  ) AS rn<br>FROM products;<br><br>-- Оставить только актуальную версию (rn = 1)``` |
| **3. CTE + рекурсивные запросы** | Миграция иерархий (например, структура подразделений в банке) | ```sql<br>WITH RECURSIVE dept_tree AS (<br>  SELECT id, name, parent_id, 1 AS level<br>  FROM departments WHERE parent_id IS NULL<br>  UNION ALL<br>  SELECT d.id, d.name, d.parent_id, dt.level + 1<br>  FROM departments d<br>  JOIN dept_tree dt ON d.parent_id = dt.id<br>)<br>SELECT * FROM dept_tree;``` |
| **4. Типы данных и приведение** | Источник (Oracle) → Приёмник (PostgreSQL) — разные типы | ```sql<br>-- Oracle DATE → PostgreSQL TIMESTAMP<br>CAST(src_date AS TIMESTAMP)<br><br>-- Обработка NULL в числовых полях (защита от падения)<br>COALESCE(amount, 0)<br><br>-- Сравнение строк с учётом регистра<br>LOWER(src_name) = LOWER(tgt_name)``` |

> ⚠️ **Не трать время на:** сложные оконные функции для аналитики, материализованные представления, оптимизацию планов запросов. Для миграции это не нужно.

## 🐍 Python: 3 критических блока для миграции

| Блок | Зачем нужно | Минимум для работы |
|------|-------------|-------------------|
| **1. Работа с файлами: Parquet / CSV** | Выгрузка из БД → промежуточное хранилище → загрузка | ```python<br># Выгрузка в Parquet (без потери типов)<br>import pandas as pd<br>df = pd.read_sql("SELECT * FROM products", conn)<br>df.to_parquet("products.parquet", engine="pyarrow")<br><br># Валидация: сравнить кол-во строк до/после<br>src = pd.read_sql("SELECT COUNT(*) as cnt FROM src", conn_src)<br>tgt = pd.read_parquet("products.parquet")<br>assert src["cnt"][0] == len(tgt), "Data loss!"``` |
| **2. Валидация данных** | Автоматическая проверка целостности после миграции | ```python<br># Сравнение агрегатов между источником и приёмником<br>def validate_migration(src_conn, tgt_conn, table):<br>    src_sum = pd.read_sql(f"SELECT SUM(amount) as s FROM {table}", src_conn)["s"][0]<br>    tgt_sum = pd.read_sql(f"SELECT SUM(amount) as s FROM {table}", tgt_conn)["s"][0]<br>    assert abs(src_sum - tgt_sum) < 0.01, f"Mismatch: {src_sum} vs {tgt_sum}"<br><br>validate_migration(oracle_conn, pg_conn, "transactions")``` |
| **3. Генерация кода миграции** | Шаблонизация повторяющихся задач (например, 50 таблиц) | ```python<br># Генератор SQL для миграции всех таблиц из схемы<br>tables = ["products", "clients", "accounts"]<br>for tbl in tables:<br>    print(f"""<br>-- Миграция {tbl}<br>INSERT INTO tgt.{tbl}<br>SELECT * FROM src.{tbl}<br>WHERE updated_at > '2024-01-01';<br>""")<br><br># Или генератор DAG для Airflow на основе YAML-описания``` |

> ⚠️ **Не трать время на:**  
> - ООП, декораторы, метаклассы  
> - Flask/Django (веб не нужен для миграции)  
> - Сложные алгоритмы (сортировки, графы)  
> - Машинное обучение
